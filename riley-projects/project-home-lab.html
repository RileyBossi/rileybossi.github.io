At-Home Cybersecurity Lab

pfSense Kali Linux Snort VMware Fusion VLANs Wireshark pfBlockerNG
Back to Projects

Overview

I built a virtual network lab on my Mac using VMware Fusion to practice real-world network security skills — firewall configuration, VLAN segmentation, intrusion detection, and traffic analysis — in a controlled environment where I could break things freely and learn from it.

There's no substitute for hands-on experience. Reading about pfSense firewall rules is very different from staring at a rule set that's blocking traffic you expect to flow, tracing the packet, and figuring out exactly why. This lab gave me that.

Lab Architecture

Host:       macOS (VMware Fusion)
Bridging:   Wi-Fi interface → virtual switch

WAN:        192.168.1.0/24   (simulated external network)
LAN:        192.168.2.0/24   (internal endpoints)
VLAN:       192.168.10.0/24  (isolated segment)

VMs:
  pfSense      — firewall, DHCP server, IDS (Snort)
  Windows 10   — two VMs simulating endpoint behavior
  Kali Linux   — attacker / analyst machine

What I Built & Practiced

Firewall Configuration (pfSense)

  • Configured interface assignments for WAN, LAN, and VLAN
  • Built and tested firewall rules controlling inter-segment traffic
  • Set up DHCP server with static mappings for VMs
  • Deployed pfBlockerNG for DNS-based ad and threat blocking

Network Segmentation (VLANs)

  • Created a VLAN (192.168.10.0/24) to isolate a VM from the main LAN
  • Wrote inter-VLAN routing rules in pfSense to control what could communicate with what
  • Verified isolation by attempting ICMP and TCP connections across segments

Intrusion Detection (Snort)

  • Deployed Snort as an inline IDS on pfSense
  • Configured rule sets and tuned alerting thresholds to reduce false positives
  • Triggered alerts using Nmap scans from Kali and verified detection
  • Analyzed Snort alerts and correlated them with packet captures

Traffic Analysis (Wireshark)

  • Used pfSense's built-in packet capture to grab traffic at the firewall level
  • Opened captures in Wireshark for deep packet inspection
  • Analyzed ICMP, DNS, and TCP handshakes to troubleshoot connectivity issues
  • Identified the exact point in the network path where traffic was being dropped

Key Takeaways

Firewalls need tuning, not just enabling

A default deny policy sounds great until legitimate traffic breaks. Learning to trace packet flow and identify which rule was responsible changed how I think about firewall management.

VLANs are a first-class security control

Segmenting the network and controlling inter-VLAN routing dramatically reduces lateral movement potential. Flat networks are dangerous — this lab made that viscerally clear.

IDS alerts need context

Snort generated a lot of noise until I tuned the rules. Learning to distinguish a scan from a real attack — and to correlate the alert with the packet capture — is the core analyst skill.

Bridging virtual and physical networks is tricky

Getting VMware Fusion to bridge over Wi-Fi (not Ethernet) surfaced a lot of edge cases around ARP, DHCP, and MAC address handling that don't show up in tutorials.
